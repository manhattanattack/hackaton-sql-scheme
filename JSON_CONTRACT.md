# Контракт подбора постоянной работы из одного промпта

Пример запроса: «Знаю C# и SQL, опыта нет. Ищу постоянную удалённую работу на полный день, 5/2, от 60 тысяч рублей в месяц».

Бэкенд/ИИ извлекает условия и сохраняет объект parsed_filters. Доступность пользователя по дням/часам не запрашивается и в БД не хранится.

```json
{
  "skills": ["C#", "SQL"],
  "search": "",
  "city": null,
  "region_name": null,
  "country_code": null,
  "include_remote": false,
  "work_format": "remote",
  "employment_type": "full_time",
  "schedule_type": "five_two",
  "contract_type": "permanent",
  "min_salary": 60000,
  "currency": "RUB",
  "salary_period": "month",
  "salary_gross": null,
  "experience_months": 0,
  "only_no_experience": true,
  "require_all_required": false
}
```

В JSON хранится именно объект. MySQL проверяет синтаксис и тип объекта; значения отдельных полей до QP02 проверяет бэкенд. Из рассказа извлекаются только подтверждённые условия; неясное значение не следует угадывать.

| Поле JSON | Куда идёт | Правило |
|---|---|---|
| `skills` | `skills` → `user_skills` | Массив названий; нормализовать, удалить дубли, синонимы только по согласованному словарю |
| `search` | `@search` Q03 | Обычно пустая строка; весь рассказ не подставлять в FULLTEXT как набор ключевых слов |
| `city`, `region_name`, `country_code` | Одноимённые параметры Q03 | NULL отключает географический фильтр |
| `include_remote` | `@include_remote` | Добавляет полностью удалённые вакансии из других городов; гибрид сохраняет привязку к месту |
| `work_format` | `@work_format` | NULL=любой, onsite=офис/на месте, remote=удалённо, hybrid=гибрид |
| `employment_type` | `@employment_type` | NULL=любая, full_time=полная, part_time=частичная, internship=стажировка |
| `schedule_type` | `@schedule_type` | NULL=любой; five_two=5/2, six_one=6/1, shift=сменный, flexible=гибкий, other=иной |
| `contract_type` | `@contract_type` | NULL=любой, permanent=бессрочная/постоянная работа, fixed_term=срочный договор |
| `min_salary` | `@min_salary` | Неотрицательное число или NULL; для сравнения нужны валюта и период |
| `currency`, `salary_period` | Параметры Q03 | Валюта и одинаковый период: hour/shift/day/week/month/year |
| `salary_gross` | `@salary_gross` | true=до налога, false=на руки, NULL=не уточнено |
| `experience_months` | `@experience_months` | Неотрицательный стаж пользователя в месяцах или NULL |
| `only_no_experience` | `@only_no_experience` | true требует явное отсутствие требования к стажу в вакансии |
| `require_all_required` | `@require_all_required` | true исключает недостающие выделенные обязательные навыки |

`@user_id` бэкенд получает по проверенному Identity principal через QA01/QA02. `@page_size` (1..100) и `@offset` (>=0) задаёт проверенная пагинация, а не ИИ. Все SQL-параметры передаются через драйвер, фрагменты SQL из ИИ не исполняются.

Полная занятость описывает объём рабочего времени, постоянный договор — срок отношений с работодателем. Это независимые условия: full_time не означает permanent. Если источник не сообщает формат, график или срок договора, в соответствующей колонке хранится unknown. Конкретный фильтр исключает unknown; NULL в параметре позволяет оставить такие объявления с пояснением «условие не уточнено». Не включайте строгий contract_type=permanent по умолчанию, когда у источника нет сведений о сроке: это может убрать всю выдачу.

Текст `schedule_text` сохраняет исходное описание графика для карточки. `schedule_type` используется для обычной фильтрации; никакого сравнения свободных часов пользователя с часами вакансии нет. «Полный рабочий день» подтверждает занятость, но само по себе не подтверждает график 5/2.

Для нового полного рассказа список skills полностью заменяет предыдущий. Пустой список очищает навыки. Режим частичного дополнения профиля требует отдельного явного правила UI/бэкенда.

## Ограничения

- Указанная верхняя граница зарплаты может достигать желаемой суммы, но не гарантирует конкретное предложение работодателя. Валюты не пересчитываются.
- Неизвестный стаж не считается нулевым. Неизвестные навыки не дают 100% совпадения.
- skill_match_percent — доля совпавших перечисленных навыков, а не вероятность найма.
- Объяснение и результат подбора относятся только к реальным vacancy_id из Q03.

## Изменение контракта для бэкенда

Удалены availability, time_zone, only_schedule_match и schedule_fit. `is_remote` заменён на `work_format`, `schedule_mode` — на `schedule_type`; добавлен `contract_type`. QA02 принимает ID аккаунта и отображаемое имя. Q11 удалён, остальные номера запросов сохранены. БД ещё не создана, скриптов переноса нет.
