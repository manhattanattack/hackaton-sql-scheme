# Данные разбора одного промпта

Это контракт хранения и вызова SQL. Сам ИИ-разбор и код API не реализуются в этом репозитории.

## Пример parsed_filters

```json
{
  "skills": ["C#", "SQL"],
  "time_zone": "Europe/Moscow",
  "availability": [
    {"day_of_week": 1, "start_minute": 960, "end_minute": 1320},
    {"day_of_week": 3, "start_minute": 960, "end_minute": 1320}
  ],
  "search": "",
  "city": null,
  "region_name": null,
  "country_code": null,
  "include_remote": true,
  "is_remote": true,
  "employment_type": "internship",
  "min_salary": 25000,
  "currency": "RUB",
  "salary_period": "month",
  "salary_gross": null,
  "experience_months": 0,
  "only_no_experience": true,
  "only_schedule_match": false,
  "require_all_required": false
}
```

`parsed_filters` — именно JSON-объект, не JSON-строка с сериализованным JSON внутри. MySQL проверяет тип объекта и синтаксис; типы/диапазоны полей внутри объекта валидирует бэкенд до QP02. Отсутствующее или неясное значение означает отсутствие подтверждённого условия, его нельзя угадывать. Допускается пустой объект, но интерфейс должен обозначить недостаточность данных для персонализации.

| Поле JSON | Куда идёт | Правило |
|---|---|---|
| `skills` | Сопоставить с `skills`, заменить `user_skills` | Массив строк, удалить дубли; синонимы только по явному словарю |
| `time_zone` | `user_profiles.time_zone` | Подтверждённый IANA-пояс пользователя; смена пояса требует корректного пересмотра интервалов |
| `availability` | `user_availability` | Дни 1..7, интервалы 0..1440 минут, начало < конца; объединить пересечения и смежные интервалы |
| `search` | `@search` Q03 | По умолчанию пустая строка; весь большой промпт не подставлять как поисковые ключевые слова |
| `city`, `region_name`, `country_code` | Одноимённые параметры Q03 | NULL отключает фильтр; для одноимённых городов использовать регион/страну |
| `include_remote` | `@include_remote` | По умолчанию false, добавляет удалённые к географической выдаче |
| `is_remote` | `@is_remote` | true=только удалённо, false=только очно, NULL=любой формат |
| `employment_type` | `@employment_type` | NULL либо full_time/part_time/temporary/seasonal/internship/volunteer/unknown |
| `min_salary` | `@min_salary` | Неотрицательное число или NULL; вместе с известными валютой и периодом |
| `currency`, `salary_period` | Параметры Q03 | При заданной сумме период hour/shift/day/week/month/year; unknown не годится для содержательного сравнения |
| `salary_gross` | `@salary_gross` | true=до налога, false=на руки, NULL=не уточнено |
| `experience_months` | `@experience_months` | Неотрицательное целое или NULL; сравнение с минимальным требованием вакансии |
| `only_no_experience` | `@only_no_experience` | true требует явное `experience_months_min=0` |
| `only_schedule_match` | `@only_schedule_match` | true исключает и конфликтующие, и неизвестные графики; по умолчанию false |
| `require_all_required` | `@require_all_required` | true исключает недостающие выделенные обязательные навыки; по умолчанию false |

`@user_id` бэкенд получает через QA01/QA02 по проверенному Identity principal, а `@page_size`/`@offset` — из проверенных параметров пагинации (1..100 и >=0), не из вывода ИИ. Вложенные имена таблиц, SQL-фрагменты и выражения из ответа ИИ не исполняются.

Для полного промпта, описывающего профиль заново, пустые `skills`/`availability` означают пустой список: старые данные удаляются, а не молча дополняются. Если UI предлагает частичное редактирование предыдущего промпта, бэкенд должен явно согласовать правила объединения; текущий SQL ориентирован на полную замену списков.

## Ограничения

- Зарплатный фильтр ищет объявления, где указанная верхняя граница (или единственная сумма) достигает желаемой. Он не гарантирует конкретное предложение работодателя.
- Отсутствие сведений о стаже или формате работы не превращается в отсутствие требований / очную работу.
- Фиксированное расписание проверяется только при полном наборе обязательных часов и совпадающих поясах. Смены, альтернативные интервалы и праздники требуют дальнейшей модели.
- Профильные навыки и свободное время могут отсутствовать; совпадения тогда не следует выдавать за подтверждённые.
- `search_results.skill_match_percent` — доля совпавших перечисленных навыков, а не вероятность найма. Объяснение относится только к реальным `vacancy_id`, возвращённым Q03.
