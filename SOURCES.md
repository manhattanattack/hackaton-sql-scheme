# Источники вакансий для хакатона

Проверено 11 ноября 2026 года из этой рабочей среды. Успешный ответ сейчас не гарантирует доступность во время защиты: храните загруженные вакансии в своей БД.

План MVP: реализуем «Работу России». HH исключён из плана демонстрации: у команды нет подтверждённого доступа к поиску вакансий. Наличие документации или доступного справочника регионов не означает доступности загрузки объявлений. Второй сайт выбираем после проверки доступа к его данным; общий интерфейс адаптеров уже предусмотрен.

## 1. Работа России — рекомендую начать здесь

- Документация: <https://trudvsem.ru/opendata/api>.
- Во время проверки основная страница документации вернула HTTP 460; её содержание доступно на служебном поддомене того же портала: <https://web-szn-demo01.k8s.trudvsem.ru/opendata/api>. Используйте его только как справку, не как источник вакансий.
- Рабочий API: `https://opendata.trudvsem.ru/api/v1/vacancies`.
- Реально проверены GET без токена: общий список и регион ДНР — оба вернули HTTP 200 и JSON `status: "200"`.
- Для прототипа начните с 50–100 вакансий по нужным профессиям, не скачивайте весь портал.
- В карточке показывайте название источника и ссылку на оригинал: это также прямо указано на странице открытых данных.

Примеры для HttpClient / браузера / Postman:

```http
GET https://opendata.trudvsem.ru/api/v1/vacancies?offset=0&limit=20
GET https://opendata.trudvsem.ru/api/v1/vacancies?text=стажер&offset=0&limit=20
GET https://opendata.trudvsem.ru/api/v1/vacancies?experienceFrom=0&experienceTo=0&offset=0&limit=20
GET https://opendata.trudvsem.ru/api/v1/vacancies/region/9300000000000?offset=0&limit=20
```

Первый и последний маршруты проверены с `limit=1/2`; варианты с текстом и опытом приведены по документации, отдельно не проверялись. Кириллицу кодируйте через `Uri.EscapeDataString` / `QueryHelpers.AddQueryString`. В JSON данные лежат в `results.vacancies[].vacancy`.

В документации есть `limit` и `offset`, но недостаточно точно раскрыта единица `offset`. Перед многостраничным импортом проверьте соседние страницы и пересечение ID; не считайте без проверки, что это номер страницы. Для первого демо достаточно одного ответа на 100 записей. Предусмотрены `modifiedFrom` / `modifiedTo` для последующих обновлений.

### Сопоставление полей с нашей БД

| Поле API | Поле БД / правило |
|---|---|
| `company.companycode` | `companies.external_id` |
| `company.name`, `company.url` | `companies.name`, `companies.original_url` |
| `company.companycode` + `id` | `vacancies.external_id = companycode + ':' + id` |
| `job-name` | `title` |
| `requirements` | `requirements` |
| `duty` | `responsibilities`; `description` составить из обязанностей, требований и условий |
| `vac_url` | `original_url`; именно его открывает MAUI-приложение |
| `region.name` | `region_name` |
| `addresses.address[].location` | `address_text`; город не всегда выделен отдельно, при неуверенном разборе `city = NULL` |
| `salary_min`, `salary_max` | Одноимённые числовые поля; отсутствие суммы не заменять нулём |
| `currency` | Нормализовать обозначение рубля в `RUB`; неизвестное значение не угадывать |
| `schedule`, `scheduleTypeComment` | `schedule_text`; schedule_type сопоставлять только с явным графиком, например 5/2/сменный |
| `creation-date`, `date_modify` | `published_at`, `source_updated_at`; timestamps перевести в UTC |
| `skills[]` | `skills` + `vacancy_skills`; удалить дубли в массиве, не объявлять каждый навык обязательным |

Период оплаты, налоговую базу, удалённость, тип занятости и единицу стажа нужно сопоставлять по подтверждённому значению/спецификации. В проверенном ответе `currency` было `«руб.»`, а период оплаты отдельным полем не пришёл. Если период не подтверждён, ставьте `salary_period='unknown'`, а не `month` по предположению. При наличии суммы без распознаваемой валюты нормализованные суммы оставляйте NULL до уточнения; сырой контактный JSON не сохраняйте. Аналогично не считайте любое `experience=0` доказательством отсутствия других квалификационных требований.

## 2. HeadHunter — справка, в MVP не подключаем

Этот раздел описывает возможное сопоставление полей, а не готовый источник данных. Не тратьте время хакатона на этот адаптер, пока у команды нет подтверждённого доступа. В демо-данных источник `hh` уже отключён (`is_enabled = FALSE`).

- Документация: <https://api.hh.ru/openapi/redoc#tag/Poisk-vakansij/operation/get-vacancies>.
- Регистрация приложения: <https://dev.hh.ru/>.
- Поиск: `GET https://api.hh.ru/vacancies?text=стажер&per_page=20&page=0`.
- Карточка: `GET https://api.hh.ru/vacancies/{id}`.
- Справочник регионов: <https://api.hh.ru/areas> — проверен, HTTP 200.
- Актуальная спецификация предупреждает о капче после первого поискового запроса без токена. Для устойчивого импорта настраивайте зарегистрированное приложение, подходящий токен и заголовок `HH-User-Agent: Название/версия (контакт разработчика)`.
- Поиск HH в этой проверке не вызывался; подтверждены документация и справочник, а не готовность авторизованного импорта.

Не путайте города: в проверенном справочнике Донецк в ДНР — `area=118`, Донецк в Ростовской области — `area=1537`, ДНР целиком — `area=2134`. Для вашего варианта «любые регионы» параметр `area` можно не передавать.

Маппинг: `id → external_id`, `name → title`, `employer.id → companies.external_id`, `alternate_url → original_url`, `key_skills[].name → skills`. У поискового результата описание сокращённое; полную карточку запрашивать отдельно. Не перезаписывайте полное описание сниппетом следующего поиска. HTML из описания очистить или безопасно санитизировать до вывода. Короткие навыки `C#`, `C++` ищите через справочник навыков, а не только FULLTEXT.

## 3. SuperJob — резерв после регистрации

- Официальная документация: <https://api.superjob.ru/>.
- Для запросов требуется секретный ключ зарегистрированного приложения в `X-Api-App-Id`.
- Пример маршрута: `GET https://api.superjob.ru/2.0/vacancies/?keyword=стажер&count=20&page=0`.
- Реальный поиск не проверен: ключ приложения не предоставлен.

На хакатоне не стоит делать этот источник обязательным, пока у команды нет ключа.

## Что передать разработчику загрузчика

1. Получить JSON через серверный `HttpClient`, с таймаутом и обработкой HTTP-ошибок и поля `status` в теле.
2. Преобразовать его в общий объект вакансии. Перед записью удалить контактные блоки и секреты; raw API JSON не сохранять.
3. Начать транзакцию; выполнить Q01 (работодатель), Q02 (вакансия); обновить навыки, только если они получены. При полноценном снимке карточки старые связи навыков заменить в этой транзакции.
4. Зафиксировать транзакцию, затем отметить успешный опрос источника. Несколько загрузчиков одного источника одновременно для MVP не запускать.
5. Повторный импорт той же пары `source_id + external_id` обновит строку, не создавая новую.
6. После загрузки пользователь ищет по MySQL. Ошибка внешнего API не должна ломать уже загруженный каталог.

Отсутствие вакансии на одной странице поиска не означает, что она закрыта. Архивируйте только при явном подтверждении источника или после отдельно реализованной полной сверки. Между разными сайтами одинаковые вакансии в MVP остаются разными строками; это честно укажите как ограничение.

## Обычные условия постоянной работы

Адаптер заполняет work_format (onsite/remote/hybrid/unknown), employment_type (full_time/part_time/internship/unknown), schedule_type (five_two/six_one/shift/flexible/other/unknown) и contract_type (permanent/fixed_term/unknown). Старые поля is_remote/schedule_mode удалены. У пользователя нет свободных часов/интервалов. «Полный рабочий день» само по себе не подтверждает 5/2 или бессрочный договор: неизвестные условия сохраняются как unknown. schedule_text содержит исходное описание для карточки.

## Node.js handoff

Канонические поля и журнал инкрементального импорта описаны в BACKEND_HANDOFF.md. Колонка raw_payload удалена. Старые search_requests/search_results заменены recommendation_runs. Источник сначала нормализуется и очищается от contact_person/contact_list/company.email и контактных блоков текста, затем пишется в MySQL.
